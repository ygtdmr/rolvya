# S2-03A human identity and primary authentication

This library implements **primary proofs**, not a production login service. It builds on merged PR #23 at `9d7c2e449ed6981618cf5aade709edd87fe4e27a`. See [ADR 0033](../decisions/0033-configurable-password-email-login-and-totp.md), the [human authentication contract](../architecture/human-authentication-implementation-contract.md) and [existing key custody](controller-key-bootstrap.md).

## Implemented boundary

[HumanAuth](../../crates/persistence-sqlite/src/controller_keys/human_auth.rs) loads the verified existing controller key without exporting it. Immutable random human IDs are separate from email addresses, worker identities and project membership. ASCII dot-atom email local-part case is preserved; domain case is normalized. Unsupported SMTPUTF8, quoted locals and address literals are rejected explicitly. No account merging or implicit roles exist.

Exact-pinned RustCrypto **argon2 0.5.3** uses Argon2id v19, OS-random 16-byte salts and 32-byte outputs. Initial engineering defaults are **19,456 KiB, two passes, one lane** (OWASP minimum profile); configurations are bounded to 65,536 KiB/four passes. Two blocking jobs per authentication instance own their permits until completion, including after caller cancellation. Private test profiles use less work; production cannot select those profiles. Stored PHCs and their user/version binding are validated before verification. Raising generation parameters retains older safe verifiers. Rehash uses the guarded versioned credential-replacement path; no opportunistic unauthenticated replacement exists. Unknown, wrong, disabled and malformed credentials produce the same external denial, with dummy Argon2 work where applicable. Production timing/abuse/load qualification is still required.

SQLite reserves failed/in-flight verification attempts before CPU work: **five/account and thirty/trusted IP per 900 seconds**, using keyed identifiers. These engineering defaults are not universal production guarantees. Failed pending work expires from the rolling window; no permanent lockout exists. Trusted client evidence is mandatory; arbitrary request IP/header values have no authority.

Magic Link is the default email method (32 random bytes); OTP uses eight uniformly sampled decimal digits. HMAC-SHA256 commitments use canonical length framing and operation/installation/key separation. They bind user, recipient, email/credential security version, policy, purpose, pending browser context, issue time and exact 600-second expiry. Short OTPs have no unkeyed offline verifier. `VerifyEmail` cannot serve as login; login cannot serve as future Owner step-up. Five failures exhaust a challenge, with additional account/IP limits across resends. SQLite serializes consumption and evidence creation. Preview never consumes; redirect targets are an enum, not arbitrary URLs.

Preparation returns a generic receipt **before** separate mail dispatch. No SQLite write transaction spans transport I/O. Queued, dispatching, transport-accepted, independently delivered and uncertain are distinct. Only independently verified delivery permits redemption. A lost acknowledgement leaves an unusable uncertain/dispatching challenge; replay never reconstructs or resends its raw bearer. Issuance is bounded (three/account and thirty/IP per 900 seconds, minimum 60 seconds between account challenges). A new challenge never resets the account guessing budget.

## Authority and persistence

Public construction denies enrollment, administration and browser operations: the reviewed local human-verification ceremony, trusted HTTPS request/CSRF correlation and independent operational mail/delivery adapters are **not implemented**. Tests install private scoped synthetic grants, never public bypasses. The first-human claim is durably reserved before hashing; interrupted claims require controlled reconciliation. It grants no Owner role. Configuration checks actual enrolled routes; enabling a method enrolls nobody, and disabling the last usable route is rejected. Pending-address users need operational verification mail independently from email-login enablement.

[Migration 0008](../../crates/persistence-sqlite/migrations/0008_human_primary_authentication.sql) adds identities, versioned email/password bindings, policy, enrollment, challenge lifecycle, throttle reservations, immutable primary evidence and append-only redacted audit. Migrations 0001–0007 are unchanged. Password plaintext, link tokens, OTPs and controller-key bytes never enter these records. PHCs are keyed to user/version to reject transplantation. Only expired throttle reservations have bounded cleanup (100/pass); security/challenge/evidence retention remains conservative pending a reviewed retention policy. Snapshot recovery requires matching existing key custody.

## Verification and remaining work

Tests in [human_auth/tests.rs](../../crates/persistence-sqlite/src/controller_keys/human_auth/tests.rs) exercise real Argon2 and SQLite, synthetic scoped transport/delivery, exact expiry, concurrent first claims/redemption/failures, withdrawn authority, cross-account/installation commitments, SQL failure/locking, restart, schema guards and password/link/OTP absence from disposable DB/WAL/snapshot bytes. Actual SIGKILL barriers cover first enrollment claim, before/after challenge commit, before/after mail send and before/after consumption commit. Two setup subprocesses also race. These are synthetic process/SQLite guarantees, not physical power-loss, real mail delivery or browser security proof. Substring scans cannot prove absence from every memory/filesystem/hardware trace.

Two independent read-only source reviewers found four distinct medium foundation defects: pending-email route lockout, generation-profile tuning rejecting existing passwords, withdrawn email verification being ignored at commit, and a harmless clock tick rejecting challenge issuance. Reproducing regressions failed before fixes and pass afterward. Review gaps prompted deterministic in-flight cancellation, transplantation and expanded crash tests. Additional model review is not Owner authorization. Exact local commands/counts and final-head CI/CodeQL belong in the PR evidence.

CodeQL follow-up: the initial head reported 27 critical hard-coded-cryptographic-value alerts. All 25 publicly visible annotations trace policy enablement booleans to a parameter misleadingly named `password`; independent inspection confirmed those flags are not credentials. Constructor/private flag names now describe method enablement, preserving SQL values, MAC inputs and real password handling. No alert is dismissed or suppressed; the separate exact-head CodeQL result remains a completion gate recorded in the PR.

**Next S2-03B:** implement one-use consumption/current revalidation of primary evidence, secure revocable server-side sessions/cookies/CSRF, seven-day human idle semantics and voluntary encrypted TOTP with replay protection. Primary results with an enrolled-factor requirement remain partial and cannot issue a session. **S2-03C:** project roles, last-Owner protection and atomic exact-action Owner proofs. Neither slice is implemented here. Production recovery, independent human enrollment ceremony, live sender, real network transport, Secret Broker consumption, worker/provider authority and emergency key recovery remain blocked. No real credentials, email, paid services or infrastructure are used.
