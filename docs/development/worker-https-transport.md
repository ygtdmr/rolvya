# S2-06A worker HTTPS transport

Implemented on verified main `4f9f1bef8bcb482c044a0f0fe4ef4606ba07d352` (merged PR #28; source matches its expected head). This is a networked synthetic worker-control library, not a deployed service or real provider integration.

## Interfaces and authority

[The HTTPS module](../../crates/persistence-sqlite/src/controller_keys/worker_auth/https.rs) stays inside the existing trusted persistence boundary so it can implement private S2-04 transport/delivery callbacks without exporting credentials, keys or an externally installable identity verifier. Its worker client contains no SQLite/store calls and receives no database path.

- `HttpsWorkerServer::open/serve`: Axum HTTP/1.1 over accepted rustls TLS connections; no public cleartext router. Production provider verification/bootstrap delivery remain unavailable.
- `ServerIdentity::from_der`: checks the configured chain and hostname against pinned public WebPKI roots, including validity. TLS 1.2/1.3; no early data. Private fixture roots exist only under `cfg(test)`. Certificate rotation constructs a validated identity and restarts the listener; trust-anchor changes require a reviewed dependency update. Neither operation resets SQLite credentials or receipts.
- `ControllerEndpoint`, `WorkerHttpClient`: explicit HTTPS origin, no userinfo/query/fragment, redirects, environment proxies or credential fallback. Bootstrap/renewal have no automatic retry. Ambiguous or failed renewal clears local credentials. Idempotent messages/assignment have at most three attempts with 100/200 ms backoff and bounded OS-random jitter; futures can be canceled by dropping them. A timeout never proves rollback.
- `wire`: version 1, strict schemas, stable outer/message IDs, bounded scope, artifact and attestation fields. Original receipt plus `Applied`/`IdempotentReplay` disposition; replay classification is returned from the existing S2-04 writer transaction, after current-authority checks. The original public `WorkerSecurity::receive` contract is preserved.
- `ResourceLimits`, `Diagnostics`: default 64 connections, two in-flight requests per scoped attempt and 240 requests/minute per peer IP, configurable within bounded ranges. These are engineering resource limits, not worker-capacity/product promises. IP windows and active TLS slots are bounded in memory; authorization and deduplication remain durable SQLite authority.

Only the TLS accept loop creates private exporter-bound request context. Headers, IDs, cookies, signed-statement strings and a bootstrap secret do not independently establish provider identity. Credential responses use the existing exact-response callbacks, opaque zeroizing credential types and a transport-owned zeroizing body. General DTO serialization does not expose credentials. HTTP/TLS library buffers are not guaranteed to be zeroized.

Requests are capped at 128 KiB, responses at 96 KiB, synthetic artifact bytes at 8 KiB; headers, TLS handshakes, request processing, queues and shutdown are bounded. A physical TLS connection has a five-minute age bound, including stalled writes; reconnecting does not reset credentials, leases or receipt authority. Retained JoinSet entries are capped as well as live connections. All network reads precede authoritative writer transactions. The handler reuses current S2-04 credentials, S2-05 entitlement/financial checks and R08 receipts. Denial-only, MAC-authenticated diagnostics distinguish scope, version, token expiry/revocation, fencing, lease expiry, financial risk, entitlement, replay conflict, throttling and storage failures; they never grant authority.

Token lifetime (15 minutes), heartbeat interval (30 seconds) and server lease (90 seconds) remain separate. Renewal does not extend a lease. `heartbeat_schedule` delays missed ticks rather than accumulating a burst. Revoked/fenced workers must exit; stop inspection/acknowledgement remains narrowly available where the existing core permits it. A stop acknowledgement never proves provider termination or releases a hold.

## Executable evidence

[Network/adversarial tests](../../crates/persistence-sqlite/src/controller_keys/worker_auth/https/tests_adversarial.rs) use real loopback TLS, an ephemeral CA and independently signed Ed25519 synthetic identity statements. Test trust constructors, signing keys, stolen-token simulation and process drivers are compiled out of production. Production `Unimplemented` identity rejects even these signed statements.

[Process tests](../../crates/persistence-sqlite/src/controller_keys/worker_auth/https/tests_process.rs) run separately identified A/B worker processes, interleave their messages, verify both durable sessions are `Executing`, and keep C blocked until independent leaf acceptance and separate G aggregation. C runs in a third worker process with predecessor commitments. Actual uploaded artifact bytes are independently hashed and compared to the immutable synthetic repository; HTTP result receipt alone creates no task success. Final SQLite reload verifies the plan fingerprint, four nodes, one explicit dependency, three attempts/launches, the original ceiling and exactly three authorized four-category reservations still held.

Actual controller subprocesses are killed with SIGKILL at six selected boundaries: before/after message commit, before/after result commit, after bootstrap issuance and after credential renewal. Reopening reuses durable receipts; committed issuance cannot retrieve a lost token, mint another generation by replay or revive the old generation. Accepted A bytes survive unrelated B fencing. No worker process receives a DB/key path.

Coverage also includes certificate chain/name/expiry rejection with a successful-TLS/401 control, valid bootstrap over rejected plaintext HTTP, forged headers/signatures, production-default denial, strict/malformed/oversized frames, escaped bearer reflection, cross-project/attempt/context requests, out-of-order and conflicting/duplicate results, corrupted artifact bytes, expiry/revocation/stale generations, financial uncertainty and provider expiry, stop/ack, concurrent renewal/revocation, shutdown during a pending response, connection/rate bounds, and raw bearer substring checks of disposable SQLite/WAL/ordinary snapshots. Substring checks are limited evidence, not proof of complete memory/storage-trace eradication.

The existing S2-05 `expiry_before_dispatch_prevents_even_provider_inspection_and_preserves_both_holds` regression additionally covers pre-launch withdrawal; the HTTP transport cannot create admission/outbox intents. Published migrations 0001–0012 are unchanged; no migration 0013 is needed.
