## Executable flow and interfaces

`rolvya_persistence_sqlite::orchestration` adds:

- `SyntheticCoordinator::open`: load and validate the active immutable plan once; retain task and child indexes. Mutable authority remains in SQLite.
- `pass` / `pass_with_adapter`: one bounded pass for expiry/failure recovery, ready-leaf admission, R08 dispatch, persisted fake-worker events, separate result verification and group roll-up. Ready reads are advisory; only existing R06 `admit` authorizes an attempt/reservation/outbox. All independent ready admissions precede worker delivery, so A and B coexist rather than imposing A-before-B execution.
- `run`: a finite deterministic **simulation driver**, advancing `DeterministicClock` to scheduled events/retry/lease deadlines. No real sleeps, busy polling, network, spawned workers or production-clock manipulation. Return `Complete`, `Blocked` or `Paused`, with typed task/project reasons. Caller-controlled passes remain usable without automatic time advance.
- `SyntheticExecutionAuthority`: mandatory injected synthetic-driver policy for scoped execution permits, capabilities, seed/behavior and peer evidence, extending existing scheduler and worker-authority traits. There is no permissive production implementation or authenticated identity claim.
- `SyntheticResultValidator::validate_leaf`, `aggregate`, `verify_accepted`, `verify_all`: independent byte verification and trusted R06 acceptance, including durable re-verification after restart.
- `snapshot` / bounded keyset `tasks`: redacted readiness, active attempts, dependency/child waits, received-but-unvalidated results, validated manifest hashes, group-validation/recovery state and rejection reasons. No prompts, artifact bytes, worker logs or credentials are exposed by these views.

The actual fixture freezes **G containing independent A/B**, with **C outside G and an explicit G → C edge**. It activates through the existing plan store and receives an explicitly synthetic budget approval through the ledger. A/B admit, dispatch and execute interleaved R07 lifecycles through R08. Successful receipts remain untrusted until independent validation. G requires verified child evidence plus its own evaluation/acceptance. C cannot admit before G acceptance; its fake output commits to G's verified manifest. Final acceptance leaves the original node/edge count and plan fingerprint unchanged. No SQLite task-status shortcuts are used.

## Independent evidence and group criteria

Migration `0005` adds immutable synthetic job specifications, bounded worker-event delivery projections, raw artifact BLOBs and validation manifests. These are simulation/evidence records, **not another ledger, dispatcher, task-state authority or planner**. Existing migrations are unchanged. Delivery projections recover against the R08 message journal; an internal already-delivered repair never returns a cached success receipt to a worker or renews expired authority.

The synthetic acceptance profile deliberately supports named test predicates only:

| Predicate | Independent check |
| --- | --- |
| `synthetic/artifact-v1` | Real stored bytes and SHA-256, strict JSON shape, expected deterministic seed, original worker/project/plan/task/attempt/epoch binding, plan/context hashes, committed dispatch provenance and read-only execution scope |
| `synthetic/inputs-v1` | Exact explicit predecessor identities and accepted manifest hashes; independently recomputed input commitment; referenced manifests and underlying artifact bytes are reverified |
| `synthetic/required-artifacts-v1` | Group has no attempt; all required children have independent accepted records and reverified artifact evidence; group-level evaluation produces its own immutable manifest and acceptance |

Unknown/missing predicates or unsupported execution scopes fail closed. This is **not a general acceptance-language implementation**. Static artifact expectations, when declared, are checked against actual `result.json` artifact hashes or `aggregate.json` manifest hashes; mismatches block admission. Runtime accepted-manifest references do not rewrite static plan expectations.

Worker artifact hashes and trusted validation-manifest hashes are separate. The validator calculates the former from actual bytes, verifies the input/context/provenance, then creates the latter from a canonical record of evaluated criteria, scope and evidence. `accept_task` commits trusted task success through a narrowly bound internal policy after the base scheduler policy grants the validation action. A candidate manifest alone is not task success; a crash/rejection between candidate storage and acceptance remains replayable and cannot unblock dependencies. The synthetic validator principal is a fixture identity, not production authentication or independent human authorization.

Group roll-up is iterative and bottom-up. Hierarchy does not add dependency edges. Two accepted children leave G incomplete until its separate group-validation step; duplicates/concurrent callbacks return the same acceptance event. Nested groups require accepted child groups. Optional-child semantics are not invented. Accepted manifests, raw bytes and frozen definitions cannot be overwritten/deleted by ordinary APIs/SQL; lifecycle archival/deletion remains a separately controlled future implementation.

## Recovery, costs and bounds

Exact scripts, frames, input commitments, artifact bytes and receipts persist before delivery. Reopening SQLite reconstructs work without regenerating an activated plan or resetting attempts/holds. Existing R08 stable-key lookup reconciles a possible launch before replay. Unrecognized legacy attempts are blocked rather than reconstructed as new synthetic work. Expiry, invalid evidence, permanent/canceled failure and uncertain operations preserve accepted siblings and reservations.

A worker transient label must match independent persisted synthetic-driver evidence; it cannot certify its own retry eligibility. Transient failure alone cannot release a hold or authorize retry. Only separately supplied trusted synthetic-provider termination/no-effect observations and explicit synthetic final financial reconciliation permit the existing R06 transient retry policy and 10/30-second delays with bounded jitter. Three total attempts remain the cap across restart; each new attempt has its own admission/reservation. Test zero-charge reconciliation is labelled synthetic and never presented as a production invoice.

`Complete` means all planned task/group evidence has been independently accepted and reverified, with no flagged financial uncertainty. **It does not mean real providers terminated or billing was finalized.** The normal A/B/G/C test retains all three four-category holds (21 synthetic minor units), with zero settled real charges and no ceiling change. Unknown exposure returns a project-level blocked reason even if task artifacts remain accepted. No automatic financial settlement, release, replacement task or budget increase occurs.

Defaults per pass: at most 16 admissions, 64 events, 16 leaf validations and 16 group validations; caller ceilings are 100/256/100/100. Driver defaults to 128 passes, maximum 1,024. Indexed worker/recovery batches and task views are at most 100 rows. Each synthetic script has at most nine frames, each at most 8 KiB; artifacts are at most 8 KiB, manifests 64 KiB, direct input/expectation sets 64, group children 128 and each iterative evidence walk 4,096 work items. Exhaustion is explicit, not an invented product-wide capacity/fairness rule. No unbounded in-memory event journal, hierarchy recursion, hidden task spawning or external operation inside a write transaction is added. Heartbeat/token/lease timing remains the R08 30/900/90-second contract.
