# Operational Connected Control panel

G1-09 extends the existing human HTTPS adapter and Connected Control application. Verified base: PR #40, `8814acf6c3b4508f57a26b12530dc86439add0a5`. This is executable Rust/SQLite/browser integration; it does not activate cloud, model, email or remote Git operations.

## Read authority and contracts

Snapshot schema **2** adds bounded operational projections. The client retains explicit schema-1 validation. Every page uses the current opaque human session, account/security generation, project membership and resource permission in the existing short SQLite transaction. Owner-only finance, connection, approval and sensitive audit rows are not materialized for Editor/Viewer readers. Read capabilities confer no command authority.

Under `/api/control/v1/projects/{project}/`, `snapshot` includes a complete bounded frozen plan and first operational windows. `attempts`, `results`, `approvals`, `connections/{model|github|aws}` and `activity/{scheduler|worker|activation|finance|governance|provider|publication}` provide independently authorized keyset pages (`limit` 1–50, default 20). Cursors are keyed commitments to project, human and resource. They are not permissions. Responses are no-store, capped at 1 MB per snapshot / 500 KB per page; task definitions and stored evidence retain their original byte/count bounds. Loading an older page replaces that source's window instead of accumulating an unbounded history.

- **Execution:** actual admission, attempt, current fence, lease, worker receipt and dispatch state. Running requires a current unexpired lease, active dispatch and executing receipt. Runtime success without R09 acceptance remains unknown. Group parents have no worker execution. Admission time is distinct from unavailable process start/end times. Raw logs remain unavailable; no prompts or arbitrary command output are returned. Counts label their page scope.
- **Finance:** the existing `finance::snapshot` applies the latest-position liability rule and checked arithmetic. Decimal minor-unit strings preserve settled, held and additional provisional amounts across AI API, compute, storage and transfer. Unknown liability disables available-headroom confirmation; forecasts without persisted trusted evidence are null. Approval history contains references/actor/version/amount/time, not passwords or reusable proof material.
- **Connections:** existing signed provider grants, Git consent and AWS registrations yield opaque project-specific display IDs. Broker references, ciphertext, keys, sessions and role credentials never enter the DTO. A recorded entitlement deadline is not proof of current production execution eligibility. Operational availability remains false while existing independent deployment/provider/spending gates are closed.
- **Results:** actual artifact bytes are hashed; acceptance manifests, coding decisions/reports and publisher receipts are checked in their owning Rust modules. Candidate, independently verified, R09 accepted and published states stay distinct. Only authenticated publication receipts expose a recorded isolated ref; no pull-request URL is invented. These readers cannot create acceptance or publish anything.
- **Activity:** source-specific durable sequence and timestamp preserve provenance. Payloads are withheld. Activation records have no persisted timestamp and return null rather than an invented date. Publisher journal metadata is authenticated. No global cross-journal chronology is claimed.

Migration **0022** adds ten project-scoped indexes only. Migrations 0001–0021 and all existing journals/ledgers remain unchanged. Upgrade/replay tests include a populated v21 database, injected transactional failure and actual query-plan checks.

## Exact Owner budget increase

`POST .../budget` accepts only the tagged stages `prepare`, `password`, `email`, `email_confirm`, `execute`; `GET .../budget/{action}` reads the requesting Owner's recorded outcome. There is no generic privileged command router. Only an existing positive financial revision may be increased; this is not initial budget setup or public enrollment.

The exact proposal contains current revision, currency, previous ceiling, new **total**, and affirmative confirmation. The browser shows the increase and unknown-liability risk. Existing `OwnerAction::budget`, preparation, fresh Argon2id/TOTP or operational email-only proof, and atomic execution remain the sole authority. Password proof does not bypass an enrolled factor. TOTP enrollment is optional. Email is unavailable without independently verified delivery; ordinary login challenges cannot substitute for action proof.

Each request retains actual TLS-exporter/body/target evidence, exact Origin and session CSRF. An internal session-generation commitment supplies the stable browser ceremony identity across HTTPS connections; it is not a claim of physical-device attestation or protection against full cookie/CSRF theft. No caller can construct trusted browser facts. Password verification occurs outside the SQLite write transaction; critical authority is rechecked inside the existing transaction.

The proof expires exactly 300 seconds after successful fresh verification. Current session/generation, security/credential/policy versions, Owner role version and exact financial version/payload are rechecked. The existing transaction applies the ceiling, consumes the action, and records audit/effect/notification intents together. Ignored mandatory writes roll back. No worker attempt, reservation, dispatch, resume or external request results from an increase. Holds and uncertain liability remain.

Unproved identical preparation retries recover the same pending action. Execution is single-use. A lost acknowledgement is never automatically replayed: the UI inspects the recorded action and refreshes REST. Same-project SSE refresh preserves the in-memory exact ceremony and pauses commands while authorization is revalidated. Project/session/permission changes clear private state; a page reload does not recover a generic privileged grant. Password/factor inputs are cleared after submission and are not stored in URLs or browser storage.

Existing backpressure, subscriber limits, session revocation, foreground-only activity and static-only Service Worker caching remain enforced.

Private offline fixtures retain the real A/B/G/C plan, separate users/projects, real R06/R08 attempts and holds, one R09 accepted coding artifact, one candidate and a trusted Git protocol publication receipt.
