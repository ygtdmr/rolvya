## Implemented code

`worker_auth::https::agent` implements one bounded `CodingWorker::execute_provider` path with four independently selected contracts: OpenAI Responses, Anthropic Messages, Codex `exec --json`, and Claude Code noninteractive JSON. It consumes existing authenticated work/source, reconstructs an attempt workspace, invokes the authorized adapter, collects exact add/modify/delete bytes, and submits existing `code_change_v1` through the real authenticated result channel. A model/CLI completion never establishes test success, R09 acceptance, spending approval or publication authority.

`CodingWork::model_account` is a separately signed-registry-derived model connection/account projection, distinct from its infrastructure provider/account. It binds integration, access mode, connection/grant/credential versions and protected credential reference. Optional omission preserves older work serialization; legacy work cannot establish provider execution. Existing current credential, lease/fence, R06/R08, project consent, S2-05 and financial checks are repeated at operation commits. Starting an operation also requires an accepted, currently Executing R08 session. The first adapter must match the connection's exact provider/integration; there is no implicit CLI/API, model or account fallback.

API adapters use documented endpoint/header and tool-call contracts, with dedicated provider request/response handling. Their only model tools read approved source, write regular source and delete approved files. No shell, arbitrary URL, network, credential, scheduler, verifier or Git tool is supplied. The bounded loop preserves provider-specific call/result messages and opaque Anthropic thinking/signature blocks unchanged, requires supported terminal assistant content and rejects replayed IDs, malformed output, unknown tools, scope changes and invalid usage. Responses use `store: false`; both use non-streaming JSON. Streaming is deliberately unsupported, not claimed tested. Context overflow fails without truncating security rules or criteria. Raw input/output token fields are observations with provider-specific semantics; missing measurements remain unknown, not zero or an invoice.

The opaque API transport binds its exact adapter, work and full model/credential identity. A narrow internal Broker consumer validates protected reference, current use authority, worker binding and account before constructing it; keys have no getter and never enter model tools, workspaces or DTOs. Network calls occur after transactions, with HTTPS-only, no-retry/no-redirect/no-ambient-proxy clients and sensitive authorization headers. Requests select literal official URLs rather than storing a URL beside credential-bearing state. Private API fixtures retain those URLs and use loopback DNS/private-CA capabilities with real certificate/hostname verification; no production custom-root or destination switch is exposed. Existing managed-worker Broker consumption still denies production use: this slice does not invent the missing trusted credential-proxy/distribution authority.

CLI adapters reject symlink/special/oversized executable files, pin executable bytes and expected version, probe documented capabilities and construct fixed argv without a shell. Probes and invocation follow a durable operation intent. Prompt data travels on stdin. Fresh per-attempt HOME/CODEX_HOME/CLAUDE_CONFIG_DIR and cleared environment prevent inherited host login/API-key selection. Codex uses workspace-write, ephemeral output and no user config/rules. Claude uses restricted/bare mode, only Read/Edit/Write and no session persistence. Bare-mode subscription authentication is not supported; hosted subscription paths remain unavailable. Credentials are not copied between homes. Neither official binary nor an authenticated vendor session was run in this milestone.

Process handling reuses G1-04's bounded, separately captured stdout/stderr and ordinary process-group cleanup. Wall time is capped by the frozen task, and authenticated heartbeats continue while awaiting provider execution. Workspace collection rejects changed root identity, symlinks, hardlinks, executable escalation, out-of-scope/sensitive paths, excessive files/bytes and unsupported file types. Original hashes, modes and line endings are preserved. Attempt-directory cleanup checks its original identity. These are ordinary execution controls, not proof against hostile same-host processes, executable replacement races, setsid, credential theft or unlimited filesystem cleanup time.

## Durable and financial boundaries

Forward **0020** adds only append-only per-attempt provider-call commitments and redacted observations under existing coding work. Published 0001–0019 and Cargo dependencies are unchanged. No new scheduler, account registry, financial ledger, worker credential issuer, acceptance engine or publisher is introduced. Metadata contains no prompts, responses, credentials or CLI diagnostics; only commitments, bounded measurements and state. Unavailable response commitments remain null rather than a fabricated placeholder hash.

The Start operation commits before external effects. Concurrent/repeated Start returns no second execution permission; a conflicting digest fails. Missing/failed completion prevents advancing. Checked cumulative per-call maxima cannot exceed the original admitted AI reservation; current R08 guards independently check all four live holds. No response, disconnect, timeout, observation or process exit releases money. Usage is not trusted settlement. A lost provider response is recorded conservatively and never automatically retried. A stale snapshot cannot undo provider reality; production establishment remains disabled and the existing restriction-only restore hold applies. Arbitrary unseen rollback detection is not implemented.

Private offline fixtures authorize **zero-cost protocol effects**, not real provider prices or enforceable spending limits. Positive budget tests also consume a synthetic integer maximum and deny an uncovered next request. Real request pricing, enforceable exposure, delayed charges, remote credential custody and billing reconciliation still require independently trusted evidence; internal token limits are not provider-side hard spending caps.

Initial engineering bounds: at most eight API requests, 64 KiB prompt/conversation and response buffers, 8,192 requested output tokens, one OpenAI tool call per response (matching its explicit no-parallel setting), up to 16 Anthropic tools per response and task-bounded wall time. Existing artifact bounds remain 256 source files/1 MiB, 16 changed files, 16 KiB per changed file and 64 KiB coding result. These are implementation limits, not universal model capabilities or production performance measurements.

## Executed offline evidence

Two A/B/G/C scenarios exercise OpenAI API + Codex CLI and Anthropic API + Claude Code CLI on distinct registered synthetic accounts. Actual Rust CLI fixture binaries and loopback TLS API servers drive the new adapters, rather than supplying prebuilt coding results. The OpenAI fixture uses five sequential API rounds; the Anthropic fixture uses three rounds with its separate multi-tool contract. Real SQLite admission/dispatch and authenticated TLS carry results from separate coding processes. Distinct independent verifier processes compile/run the harmless pinned tests. Existing R09 accepts, G aggregates, C obeys its original dependencies and GitHub HTTP fixtures reconstruct two isolated refs with exact full file bytes. A modifies/adds/deletes; B changes its own file. Frozen fingerprints and approved ceilings remain unchanged; protected refs are untouched.

Regressions reproduce and correct transport/credential scope substitution, root-directory symlink substitution, malformed terminal success and pre-lease provider authorization. Additional cases cover account/mode/model/effort/version substitution, invalid usage, unsupported tools, context limits, actual partial HTTPS response loss, quota/rate/auth/provider failures, no retry, concurrent starts, budget exhaustion, terminal-session denial, ignored writes, cleanup and expiry. A syntactically valid but wrong API-generated change is also rejected by an actual independent verifier subprocess before R09 or publication. Four actual SIGKILL cases straddle call-intent and observation commits, preserving a previously accepted sibling and original holds. Migration tests cover populated v19 upgrade and injected v20 rollback. Exact unique counts, final commands, review and CI evidence belong to the PR; nested subprocess cases and repetitions are not additional root tests.
