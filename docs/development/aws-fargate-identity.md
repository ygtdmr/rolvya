# S2-06B AWS Fargate inspection and bootstrap boundary

Base: merged [PR #29](https://github.com/ygtdmr/rolvya/pull/29), main `4563e915ea8910b203869ca8b170234427f43ee7`; its source tree matches `86b2a12ca40626ff999b6338c1ee1b384faa4779`.

## Implemented foundation

[The AWS module](../../crates/persistence-sqlite/src/controller_keys/worker_auth/aws_fargate.rs) provides validated AWS account/partition/cluster/task/task-definition/role identities, bounded Linux Fargate workload configuration, official SDK response inspection and durable controller-side correlation. Long ECS task ARNs are required; unsupported forms fail closed. These data contracts confer no authorization.

`FargateIdentity::enroll_account`, `record_execution` and `inspect` use the existing controller key, SQLite, encrypted Broker reference, R06 admission/reservation, S2-05 eligibility and R08 dispatch scope. Sealed infrastructure-consent and explicit credential-resolution boundaries are unavailable in production; callers cannot inject their own verifier. Tests use private scoped fixtures, never production enrollment or live credentials. The fixture's encrypted Broker record proves reference/integrity isolation; its independent synthetic SDK credential source does **not** demonstrate a completed production Broker credential-consumption adapter.

Forward [migration 0013](../../crates/persistence-sqlite/migrations/0013_aws_fargate_identity.sql) stores versioned infrastructure accounts, immutable execution bindings and append-only inspection revisions. Scoped foreign keys bind observations to the execution's exact account version. Installation-keyed MACs authenticate bounded records; account heads use version checks and observations use compare-and-set publication. History is retained, with at most 2,048 observations per attempt; no automatic evidence cleanup or new financial ledger exists. Published migrations 0001–0012 are unchanged.

SDK calls run outside SQLite transactions. Publication rechecks current consent, credential reference, account, immutable execution, previous revision and current fencing/financial scope. Concurrent revocation or a newer observation prevents stale publication. Replaying a receipt requires present authorization and a freshness window of less than 15 seconds. A separately authorized status inspection may outlive worker execution authority for reconciliation; it cannot revive that authority.

The production SDK connector accepts only regional AWS HTTPS `GetCallerIdentity`, `DescribeTasks` and `DescribeTaskDefinition`. Explicit credentials are mandatory; there is no `aws-config`, environment/default chain, endpoint override, redirect, proxy inheritance, launch or stop path. Requests/responses, timeouts and connection pooling are bounded; SDK retries are disabled. Throttling, partial failures, absence, contradictory states and unknown outcomes fail conservatively. AWS request bodies and credentials are not logged.

Correlation checks exact task/account/partition/region/cluster, task-definition revision, registered controller role ID, distinct task/execution roles, operation reference, immutable image digest, CPU/memory/disk, platform, user, read-only/nonprivileged single-container configuration, entry point, command, mounts, environment, execution override and subnet observations. Reviewed security-group/VPC/IAM references remain configuration requirements, not independent evidence of effective network/IAM policy. Runtime limits remain declared limits, not an enforceable final billing bound.

`HttpsWorkerServer::open_fargate` selects the concrete AWS adapter within the existing S2-06A TLS server. Its private request snapshot originates in the actual accepted TLS handler, not JSON or headers. The adapter correlates a registered execution and persisted AWS inspection, then **denies credential issuance**. It never constructs an S2-04 `IdentityGrant`. S2-04's one-use challenge/token/lease/renewal rules are preserved, not replaced. Protected bootstrap delivery is unavailable.

## Why production issuance remains disabled

Official documentation reviewed on **2026-10-29**:

- [ECS task IAM roles](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-iam-roles.html): task ARN appears in CloudTrail session context. This is not a documented caller-presentable, challenge-bound per-task attestation.
- [STS GetCallerIdentity](https://docs.aws.amazon.com/STS/latest/APIReference/API_GetCallerIdentity.html): returns Account/Arn/UserId. Controller identity verifies the configured inspection caller; it does not prove a worker controls a particular task. [AssumeRole](https://docs.aws.amazon.com/STS/latest/APIReference/API_AssumeRole.html) permits caller-selected role-session names; a task-like suffix is insufficient authority.
- [Task metadata](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-metadata-endpoint-v4-response.html): values received from workers are untrusted hints, not attestation.
- [RunTask](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_RunTask.html), [DescribeTasks](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_DescribeTasks.html) and [ECS idempotency](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ECS_Idempotency.html): eventual visibility and partial failures require reconciliation. RunTask tokens are cluster-scoped, at most 64 ASCII characters, with a bounded window (the lesser of 24 hours and task lifetime plus one hour). The stable operation digest is public correlation, never authentication or an indefinite exactly-once guarantee. No launch retry is implemented.
- [IAM role separation](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/security-iam-roles.html), [task definitions](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_TaskDefinition.html), [ephemeral storage](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_EphemeralStorage.html) and [Fargate networking](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/fargate-task-networking.html) inform configuration validation; they do not verify this deployment's permissions, isolation or final charges.

Missing evidence: independently authorized production infrastructure enrollment and Broker credential consumption; fresh per-task possession bound to the controller challenge and exact TLS request; protected one-use bootstrap delivery; effective IAM/network policy; enforceable remaining financial exposure; and isolated real-cloud validation. No AWS-signed proof format or undocumented task-session-name guarantee is invented. The user-authorized conservative fallback is implemented; production native attestation/bootstrap remains blocked.

No `RunTask`/`StopTask` operation is reachable through this adapter. Inspection, disconnect, fencing, lease expiry, STOPPED status and cancellation acknowledgements never release a financial hold or establish final billing. Real stop/termination/cost reconciliation and client-token expiry behavior require later trusted adapters and authorized cloud evidence. Existing R08 authority remains responsible for reconciliation.
