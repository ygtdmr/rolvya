# Brand evolution, license choice and asset provenance

## Why this record exists

The Rolvya naming, visual and licensing conversation contained several **successive preferences**. Preserving the full evolution is useful for later AI coding agents, but **earlier variants must not overwrite the last explicit owner-approved direction**. The current design status is described in [brand positioning](brand-positioning.md); the [decision register](../decisions/README.md) governs accepted product policy.

This reconstruction is based on **retrievable historical conversation excerpts and summaries**, not a line-by-line complete transcript. Artwork itself, an editable SVG master and a formal trademark clearance report were not available as verified repository files during this audit. Do not invent exact final HEX values or claim any logo vector file has been validated.

## Naming timeline and current rule

1. The user wanted a short, natural-sounding single-word technology identity and prioritized conflict checks on **GitHub and X**. Earlier proposals including **Dagyro** and **Velnqo** were rejected.
2. **Rolvya** was selected. It is a coined name with no established dictionary meaning, acronym expansion or direct linguistic claim about DAGs/agents.
3. Prior quick search observations are not a trademark or username/domain guarantee. Github/X account availability and commercial trademark conflicts **must not** be declared cleared from historical snapshots.
4. **Approved:** name **Rolvya** with normal capitalization; spelling **Rolvya** in official repository and user-facing copy. Do not rename or invent an expansion.

## Licensing history and important correction

1. User worried that another company might take the public source and create a commercial competitor.
2. Discussed **MIT**, **Apache-2.0** and **GNU MIT**: permissive MIT, Apache's explicit patent provisions, MIT's permissive requirements on qualifying distributions. All generally permit commercial activity; MIT is **not** a noncommercial license.
3. An earlier assistant response mistakenly wrote **MIT** after the user selected MIT. The user corrected/confirmed the choice.
4. **Final binding license: GNU MIT (`MIT`)** as recorded in the repository [LICENSE](../../LICENSE), not MIT and not an additional no-commercial-use clause.
5. The owner's commercialization concern remains real, but **cannot be “fixed” by falsely stating that MIT forbids competing services or companies**. A future trademark/brand-use policy is a separate legal/product decision and should not silently conflict with MIT source rights.

No legal opinion or trademark registration is implied. Future organization transfer, dual licensing, contributor agreements, source attribution and brand/logo usage rules require separate legal review and explicit owner decisions.

The user also discussed proposed GitHub repository discovery topics such as `ai-agents`, `multi-agent`, `orchestration`, `coding-agents`, `developer-tools`, `open-source` and `DAG`. These are **historical suggested metadata**, not proof that all topics were actually configured on the repository. The repository About/topics require separate authorized settings changes and review.

## Anti-regression checks for AI agents

- A branding PR introducing gold/brass from an old prompt without new owner approval is rejected.
- A license document that says MIT or forbids all commercial competition is inconsistent with approved MIT.
- A speculative “Rolvya means …” etymology or guaranteed unique name conflicts with source evidence.
- A README update inserting the tagline in multiple sections is inconsistent with the writing preference.
- A new logo SVG drawn from text description cannot be labeled the final approved logo.
- A move to an organization, another license or protected brand governance requires explicit owner authorization.
